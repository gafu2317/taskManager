# マスコット育成機能 設計書

**最終更新**: 2026-02-22
**ステータス**: 設計中（実装未着手）

---

## コンセプト

「ポイントを稼いで、マスコットの性格を自分好みに育てる」育成。
絆・マイルストーンの概念はなし。

**主な変化：**
- 性格パラメータへのポイント配分 → セリフ・口調が変わる
- アクセサリーをポイントで購入 → 見た目が変わる

---

## ポイントシステム

### ポイントの獲得

| アクション | 獲得 |
|---|---|
| タスク完了 | +10 pt |
| 作業セッション終了（30分あたり） | +10 pt（`floor(workSeconds / 1800) * 10`）|
| ログイン（1日1回） | +5 pt |

> ポイントは「所持ポイント（残高）」と「累計獲得ポイント」の両方を記録する。
> アクセサリー購入・性格パラメータ配分は所持ポイントを消費する。

### ポイントの使いみち

| 用途 | 消費 |
|---|---|
| 性格パラメータへの配分 | 後述（再配分は自由） |
| アクセサリー購入 | 後述（購入は永続・ポイントは戻らない） |

## 性格パラメータ

### 概要

ポイントを消費して各パラメータのレベルを上げる。
パラメータの値の組み合わせがマスコットのセリフの口調・内容を決定する。

**再配分**: いつでも全パラメータをリセットし、消費したポイントを全額回収して再投資できる。
アクセサリー購入に使ったポイントは戻らない（永続消費）。

### パラメータ一覧（6軸）

| # | パラメータ | 低い（Lv0） | 高い（Lv10） |
|---|---|---|---|
| 1 | **元気** | 穏やか・静か・落ち着いた口調 | テンション高め・積極的に励ます |
| 2 | **厳しさ** | やさしく褒める・甘め | ストイックに叱咤・妥協しない |
| 3 | **甘え** | あっさり・クール・距離感あり | 懐いてくる・スキンシップ的な言葉 |
| 4 | **ツンデレ** | 素直に感情を出す・正直 | 素直じゃないが本音が滲む表現 |
| 5 | **真面目** | フリーダム・気まぐれ | 実績・数値・進捗を引用してくる |
| 6 | **天然** | 普通の受け答え | ちょっとズレた・独自視点のセリフ |

### レベルとポイントコスト

- 各パラメータ: Lv 0〜10
- コスト: **固定（1Lv = 10 pt）**

### セリフ生成戦略

**方針**: 最上位パラメータ（最もLvが高い軸）が口調の「キャラクター」を決め、
2位以下は副次的な色付け程度にとどめる。組み合わせ爆発を避けるため。

```
例: 元気 Lv8, 厳しさ Lv3, 甘え Lv1, ... の場合
→ 「元気キャラ」のセリフプールから選択
→ 厳しさが一定以上あれば「頑張れ」系ワードが追加される程度
```

**セリフの実装方法（優先順）:**

1. **AIリアルタイム生成**（理想）
   - セリフ表示のたびにLLM APIを呼び出す
   - パラメータと状況（コンテキスト）をプロンプトに含める
   - コストが高いため現実的でない可能性あり

2. **AIで事前生成 → 静的ファイル**（現実的）
   - パラメータパターン × コンテキストの組み合わせを一括生成
   - 生成結果をJSONとしてフロントエンドに同梱
   - 追加したいときだけ再生成する運用

3. **手書き**（フォールバック）
   - コンテキスト × 主要パラメータキャラの組み合わせを手書き
   - ボリュームは少なくなるが確実に動く

## アクセサリー

### 概要

ショップでポイントを消費して購入。購入は永続（消費したポイントは戻らない）。
購入したアクセサリーはいつでも装備・外しが可能。

### アクセサリー候補（未確定）

## データモデル（DynamoDB）

### テーブル: `MascotData`

```
PK: userId (String)
SK: "mascot" (固定)

fields:
  currentPoints          Number   現在の所持ポイント（残高）
  totalEarnedPoints      Number   累計獲得ポイント
  personalityParams      Map      各パラメータへの配分ポイント
                                  例: { "genki": 30, "kibishisa": 10, ... }
  ownedAccessories       List<String>   購入済みアクセサリーID一覧
  equippedAccessories    List<String>   装備中アクセサリーID一覧
  lastLoginDate          String   ISO日付 (YYYY-MM-DD)（1日1回ログインボーナス用）
  createdAt              String   ISO timestamp
  updatedAt              String   ISO timestamp
```

## API設計（バックエンド）

```
GET  /api/mascot                   → マスコットデータ取得
POST /api/mascot/action            → ポイント獲得アクション記録
POST /api/mascot/personality       → 性格パラメータの配分変更
POST /api/mascot/shop/buy          → アクセサリー購入
PUT  /api/mascot/equip             → アクセサリー装備変更
```

### POST /api/mascot/action

```json
{ "type": "task_complete" }
{ "type": "work_session", "workSeconds": 3600 }
{ "type": "login" }
```

### POST /api/mascot/personality

配分後の状態をまるごと送る（差分ではなく全量）。
バックエンドで「配分合計 ≤ 所持ポイント」を検証する。

```json
{
  "params": {
    "genki": 30,
    "kibishisa": 10,
    "amae": 0,
    "tsundere": 0,
    "majime": 5
  }
}
```

### POST /api/mascot/shop/buy

```json
{ "accessoryId": "crown" }
```

## フロントエンド

### 画面構成（案）

```
マスコットパネル
├── マスコット表示（Mascot.tsx）
├── 所持ポイント表示
├── [性格設定] ボタン → 性格パラメータ配分UI
└── [ショップ] ボタン → アクセサリーショップUI

性格パラメータUI
└── 各パラメータ: スライダー or 数値入力
    （合計消費ポイントが所持ポイントを超えないようリアルタイム検証）

ショップUI
└── アクセサリー一覧（価格・購入状況・装備状況）
```

### セリフシステム

`useMascot` フックを拡張し、性格パラメータを受け取ってセリフを決定する。

```ts
type PersonalityParams = {
  genki: number;
  kibishisa: number;
  // ...
};

function getDialogue(mood: MascotMood, params: PersonalityParams): string
```

## 実装順序（案）

1. **Phase 1: バックエンド基盤**
   - `MascotData` テーブル作成
   - `GET /api/mascot` `POST /api/mascot/action` 実装
   - ログイン日付チェックロジック

2. **Phase 2: 性格システム**
   - 性格パラメータの軸を確定
   - セリフテーブル作成（パラメータ × コンテキスト）
   - `POST /api/mascot/personality` 実装
   - フロントエンドの性格配分UI

3. **Phase 3: ショップ**
   - アクセサリーの品揃え・価格・ビジュアル確定
   - `POST /api/mascot/shop/buy` 実装
   - ショップUI・装備UI実装

4. **Phase 4: 各機能との連携**
   - タスク完了時にポイント付与
   - 作業セッション終了時にポイント付与
   - ログイン時にポイント付与
